# МедКонтроль на iPad

Полноценная редакция без сервера: история лечения, файлы и напоминания работают на самом планшете.
Технически это то же приложение, что в настольной версии, но целиком внутри страницы WKWebView:
gateway (Fastify) отвечает через `app.inject()`, база — PGlite (Postgres в WebAssembly) в IndexedDB,
оболочка — Tauri 2. Причина: iPadOS не запускает сторонние процессы, а JIT и WebAssembly доступны
только встроенному браузеру. Ветка разработки: `ipad/real-ui`.

## Редакция

`DTC_EDITION=ipad` — это настольная редакция плюс один запрет: Telegram (`IPAD_ONLY` в
`gateway/src/lib/edition.js`). Как и на desktop, недоступны серверные функции: Apple Health, DICOM,
ночные бэкапы, ключи входа (passkeys), egress-прокси. Интерфейс показывает их с пометкой «доступно
только в серверной версии». Напоминания на iPad ставит сама система (локальные уведомления),
а не бот.

## Данные и их сохранность

- **Основное хранилище** — IndexedDB внутри WKWebView: база PGlite (`/pglite/medcontrol`) и файлы
  папки данных (`medcontrol-files`).
- **Копия в контейнере приложения** (`medcontrol/` в данных приложения, плагин fs): каждый записанный
  файл копируется сразу, снимок базы (`dumpDataDir`) — раз в две минуты и при уходе в фон, только
  если после прошлого снимка были записи. Снимок пишется атомарно, предыдущее поколение хранится
  рядом (`pgdata.tar.prev`).
- **Восстановление**: если IndexedDB пуста (iPadOS может чистить хранилище WebView), при старте
  копии из контейнера проверяются открытием базы в памяти. При повреждении последнего снимка приложение пробует предыдущее поколение, затем временный снимок. Если все копии повреждены, запуск останавливается для восстановления данных. Нужен `indexedDB.databases()`, поэтому минимальная версия —
  **iPadOS 17.4**.
- **Защита от перезаписи**: пустая база (первый запуск не пройден) и неудачное восстановление
  (`__MC_RESTORE_FAILED`) никогда не пишут снимок поверх копии.
- **Резервная копия для пользователя** — «Архив всех данных» в настройках, сохраняется через
  системное меню «Поделиться» (в «Файлы», iCloud и т.д.). Восстановление — импорт архива с паролем.
- Копия в контейнере попадает в резервные копии iOS (iCloud/iTunes). Это стоит учитывать:
  данные истории могут оказаться в облачном бэкапе Apple.

## Напоминания

Системные уведомления (`mc-notify.js`, плагин notification): приёмы препаратов, визиты к врачу,
курсы капельниц, «давно не было анализов», тревоги. За один проход ставится не больше 60 уведомлений;
система хранит ближайшие 60 датированных событий. Приложение пополняет очередь при открытии, изменении схемы или отметке дозы и каждые 15 минут, пока оно открыто. Когда все 60 событий прошли, для продолжения требуется снова открыть приложение. Тревоги передаются отдельно. Кнопки «Принято» и
«Пропустить» записывают отметку о приёме. Время считается по поясу iPad на момент постановки:
после перелёта уже поставленные уведомления сработают по-старому, пока приложение не перепланирует их.
Названия препаратов видны в уведомлениях на локскрине — это особенность системных уведомлений.

## Замок Face ID

Сессия живёт 30 дней, как в других редакциях. На iPad история дополнительно закрыта замком Face ID
(`FaceLock.tsx`, команда `face_unlock`): при запуске и при возврате из фона. Запасной вход — пароль
МедКонтроля; после блокировки биометрии пароль предлагается сразу. Это **приватный экран**, а не
граница безопасности: gateway и токен живут в той же странице, настоящая граница — пароль-код
устройства. Ключи входа (passkeys) остаются только в серверной версии.

## Загрузка файлов

WKWebView не принимает программный `click()` по скрытому полю файла и не заканчивает разбор
multipart через `app.inject`. Поэтому в статической сборке поле лежит поверх подписи
(`FileButton`, флаг `NEXT_PUBLIC_STATIC_EXPORT`), байты читаются сразу при выборе, а загрузка идёт
напрямую в те же функции ядра, что вызывают маршруты (`commitLabsPdf` и др.), мимо multipart.
Общие ответы ошибок и чтение multipart живут в gateway (`lib/labsCommit.js`, `lib/multipart.js`).
Серверная и настольная редакции загружают файлы по-прежнему.

## Язык интерфейса

Статическая страница собирается с языком по умолчанию; после открытия берётся кука `mc_lang`,
иначе сохранённые настройки, иначе язык браузера. Смена языка не требует сервера: словари уже
в странице. Тексты страничных скриптов (уведомления, просмотр файла) — в `locales/<язык>/ipad.json`.

## Сборка и запуск

Нужны Xcode, симулятор iOS, `xcodegen`, `cocoapods` (Homebrew), цели Rust `aarch64-apple-ios` и
`aarch64-apple-ios-sim`, команда подписи Apple.

```bash
(cd gateway && npm ci) && (cd frontend && npm ci)
cd ipad && npm ci
node build.mjs && node build-frontend.mjs        # веб-часть и статический интерфейс
npm test                                          # тесты страничной части
TAURI_APPLE_DEVELOPMENT_TEAM=<команда> npx tauri ios build --target aarch64-sim --debug --ci
```

Без устройства: `python3 serve.py 3801` и http://127.0.0.1:3801/ в браузере на Mac.
Релизная сборка: `MC_RELEASE=1` для обоих build-скриптов — тестовая страница `spike.html`
и фикстура `rows.pdf` не попадают в бандл. Команда подписи не хранится в репозитории.

## Обходные пути: почему сборка патчит то, что патчит

Ограничения WKWebView потребовали обходов; все они локализованы в сборке (`ipad/build.mjs`,
`build-frontend.mjs`) и страничных скриптах, код gateway почти не тронут. При обновлении
зависимостей патчи проверяются на совпадение и валят сборку, если исходник изменился.

- `process.nextTick` из полифилла шёл через `setTimeout` (минимум 4 мс) — запуск занимал 12 с;
  на микрозадачах — миллисекунды. `setImmediate` — на MessageChannel.
- PGlite принимает страницу за Node, если в `process.versions` есть `node` — версию не выставляем.
- Логгер pino в браузерной сборке не подходит Fastify: логгер выключен, ошибки идут в консоль.
- `graceful-fs` (архив) подменяет методы `fs` и требует `fs.ReadStream` — шим даёт потоки.
- Секрет токенов (`jwt.secret`) должен переживать перезагрузку — файлы папки данных в IndexedDB.
- WKWebView не принимает программный `click()` по скрытому `<input type="file">` — в статической
  сборке поле лежит поверх подписи (`FileButton`), байты читаются сразу при выборе.
- Разбор multipart через `app.inject` на устройстве не заканчивается — загрузка идёт напрямую
  в функции ядра, мимо multipart (те же функции, что вызывают маршруты).
- Модульный worker pdf.js в WKWebView может не ответить — pdf.js работает в основном потоке;
  адреса `tauri://`/`asset:` добавлены в протоколы fetch, динамический импорт декодера картинок отключён.
- pdfkit ищет шрифты через `__dirname` — файлы вложены в сборку (виртуальная ФС).
- Next с `trailingSlash` отдаёт `/login/` — оболочка интерфейса узнаёт страницу входа с косой чертой.
- Воскрешение удалённого файла возможно, если краш случился между удалением из IndexedDB и контейнера.

## Замеры

Сняты в Chromium, Safari 27 на Mac и в приложении Tauri на iPad Air 11 **в симуляторе**
(iPadOS 27.2), на вымышленном бланке `ingestion/tests/fixtures/pdf/rows.pdf`.
Симулятор работает на процессоре Mac — на настоящем iPad цифры будут другими; замеры старта
нужно снять заново после исправления `loadCatalog`.

| Шаг | Chromium | Safari | iPad, симулятор |
|---|---|---|---|
| Первый запуск на пустой базе | | | 22,6 с |
| Повторный запуск | 2,4–3,8 с | 7,7 с | 10,9 с |
| Первый запуск мастера или вход | 0,2 с | 0,1 с | 0,6 с / 0,1 с |
| Разбор бланка PDF встроенным парсером | 0,47 с | 0,06 с (повторный) | 1,0 с |
| Сводка анализов | 0,09 с | 0,17 с | 0,15 с |
| Отчёт для врача, PDF | 0,4 с | 0,9 с | 0,8 с |
| Сводка в Excel | 0,13 с | 0,4 с | 0,4 с |
| Архив всех данных, ZIP | 0,8 с | 2,4 с | 2,1–2,3 с |

Разбор PDF идёт в главном потоке: обычный бланк после первого раза около 6 мс, первый в сессии
около 150 мс. Восьмистраничный скан A4 (2480×3508) не держит поток дольше 100–150 мс за раз;
одна страница в памяти около 26 МБ, восемь страниц подняли процесс примерно до 430 МБ (замер на Mac).
Размер сборки: `gateway.js` около 19 МБ без сжатия, вместе с PGlite и интерфейсом около 40 МБ.

## Ограничения и что проверить на устройстве

- Telegram выключен; напоминания — системные, работают и при закрытом приложении.
- ИИ-запросы из страницы могут упираться в CORS; при необходимости — через плагин HTTP Tauri.
- Распознавание сканов: модели в приложении, таймауты 45/60 с; память на живом iPad не замерялась.
- Хранилище WebView: очистка iPadOS не воспроизводилась на живом устройстве; восстановление из копии
  проверено только в симуляторе.
- Снапшот переключателя приложений может сняться до перерисовки в замок Face ID.
- **Отметка «Принято» из уведомления при убитом процессе.** В tauri-plugin-notification 2.8.1
  обработчик действия безусловно разыменовывает карту уведомлений в памяти, которая после холодного
  запуска пуста: возможен краш обработчика. Проверить на устройстве; до проверки не полагаться на
  отметку из уведомления при закрытом приложении (обход — патч плагина или подтверждение при следующем открытии).
- Снимок базы при уходе в фон может не успеть завершиться (WKWebView быстро замораживается):
  последняя надёжная точка восстановления — снимок до ухода в фон.
- Восстановление опознаёт базу PGlite по имени IndexedDB (`/pglite/medcontrol`): при обновлении
  PGlite имя проверить. Незавершённые операции записи и удаления файлов из контейнера повторяются при следующем запуске.
- Большие архивы (десятки–сотни МБ) импорт на iPad может не пережить по памяти: буфер целиком
  в WebView. Временный файл импорта не копируется в IndexedDB и контейнер.
- До публичного выпуска: релизный идентификатор приложения, подпись App Store/TestFlight,
  ужесточение CSP (хэши вместо `unsafe-inline`), русская локализация `NSFaceIDUsageDescription`,
  `ITSAppUsesNonExemptEncryption`, решение по бэкапам контейнера, статус резервирования в интерфейсе.
