# Настольная версия (macOS и Windows)

Приложение целиком работает внутри настольного: окно Tauri 2, рядом встроенный Node,
база PGlite (Postgres в WebAssembly) вместо сервера Postgres, PDF читается на JS. Без Docker, без своего сервера,
данные в папке пользователя.

Здесь описано, чем настольная версия отличается от серверной, как её собрать и как она устроена.

## Редакции: что есть только на сервере

Код один. Переменная `DTC_EDITION=desktop` выключает то, что настольное приложение сделать не может; интерфейс оставляет
эти функции на месте с пометкой «только в серверной версии» и объяснением. Сервер на прямой запрос отвечает 409 `server_only`.

| Функция | Ключ | Почему нет в настольной версии | Что видит пользователь |
|---|---|---|---|
| Apple Health | `appleHealth` | телефон отправляет данные на адрес сервера в интернете | карточка-пояснение вместо настройки; строка в Настройках «только в серверной версии» |
| Архив снимков DICOM (Orthanc) | `dicom` | отдельный сервис Orthanc | кнопка «Архив снимков · только в серверной версии» неактивна |
| Ночные бэкапы | `backups` | служба `backup` сервера | пояснение: сохранять «Архив всех данных» в iCloud, OneDrive или на флешку |
| Ключи входа (passkey) | `passkeys` | привязаны к адресу сайта | вход по паролю; карточка ключей — пояснение; кнопки «Войти по ключу» нет |
| Прокси для ИИ и Telegram | `egress` | контейнер `egress` | нет кнопки «Откуда идут запросы» |

Работает и в настольной версии: всё остальное, включая ИИ, MCP для локальных агентов (Claude Desktop на том же компьютере),
Telegram-бот и напоминания — пока приложение открыто (интерфейс об этом предупреждает).

Как устроено: `gateway/src/lib/edition.js` (`edition()`, `available(feature)`, `requireFeature(feature)`, `SERVER_ONLY`),
публичный `GET /edition`, во фронтенде `useEdition()` (`frontend/app/ui/edition.ts`) и `<ServerOnly>` с текстами
причин (`frontend/app/ui/ServerOnly.tsx`). Новая функция, которой не будет на десктопе: ключ в `SERVER_ONLY`,
`requireFeature` в маршруте, `ServerOnly` или пометка в интерфейсе, строка в таблице выше.

## Как собрать

Нужны Node 22+, Rust (stable, через rustup) и для Windows — WebView2 и инструменты сборки MSVC.

```bash
cd frontend && npm ci && cd ../desktop && npm ci
npm run build                     # ресурсы + релизная сборка: .app/.dmg на macOS, установщик .exe на Windows
npm run dev                       # то же в режиме разработки (окно Tauri, отладочная сборка)
node scripts/prepare.mjs --target x86_64-apple-darwin && npx tauri build --target x86_64-apple-darwin   # Mac на Intel
```

`desktop/scripts/prepare.mjs` готовит то, что едет в пакете: Node 22.23.4 с nodejs.org (сверка с `SHASUMS256.txt`)
в `src-tauri/binaries/node-<target>`, а в `desktop/build/app/`: gateway с production-зависимостями (с PGlite, без нативного
`@napi-rs/canvas`), `shared/`, `locales/`, `db/migrations`, сборку Next `standalone` со `static` и `public`. Карты исходников и `.d.ts`
удаляются; если в пакете окажется нативный модуль (`.node`), скрипт останавливается. Раскладка повторяет репозиторий.
Готовое приложение: `desktop/src-tauri/target/release/bundle/`. Сборки без подписи разработчика.

Идентификатор приложения `app.med-control.desktop` (папка данных от него не зависит: она называется `MedControl`), иконки собраны из знака на синей плитке (см. `docs/brand/README.md`,
`npx tauri icon …`). Для проверки без настоящей папки данных: `DTC_DATA_DIR=/tmp/mc <путь к приложению>/Contents/MacOS/medcontrol`.

## Как устроено

Всё настольное включается переменными окружения; без них серверная версия работает как обычно.

### 1. Драйвер PGlite в `gateway/src/lib/db.js`

`gateway/src/lib/pglite.js` (фасад) и выбор драйвера в `db.js`; PGlite 0.5.10 (внутри Postgres 18) закреплён точной версией
в `optionalDependencies` — серверный образ ставит зависимости с `--omit=optional` и не растёт; для настольной сборки
ставить без `--omit=optional`. Сессия PGlite в UTC, как Postgres в контейнере. Сервер при SIGTERM закрывает базу (`pool.end()`), чтобы PGlite дописал файлы.
Интеграционные тесты в CI идут дважды: на Postgres и с `TEST_DB=pglite` (`gateway/test/integration/helpers.js`: свежая PGlite
в памяти на файл вместо `create database`). Юнит-тесты фасада: `gateway/test/pglite.test.js`.

- `DB_DRIVER=pglite` (по умолчанию `pg`), папка базы `PGLITE_DIR` (по умолчанию `DTC_DATA_DIR/pgdata`).
- PGlite с расширением `pgcrypto` из `@electric-sql/pglite/contrib/pgcrypto` (миграция 001 делает `create extension pgcrypto`).
  Все миграции, русский полнотекстовый поиск, часовые пояса, `jsonb` и advisory-блокировки работают.
- Фасад, похожий на `pg.Pool`, чтобы остальной код не менялся: `pool.query(sql, params)` → `{ rows, rowCount }`
  (в PGlite поле называется `affectedRows`), `pool.connect()` → клиент с `query` и `release`.
- **У PGlite одно соединение**, поэтому фасад пускает запросы по очереди: `connect()` держит замок до `release()`,
  `transaction(fn)` от `BEGIN` до `COMMIT`, `query()` вне транзакции ждёт его.
- Типы как у `pg`: дата (`DATE`) строкой `ГГГГ-ММ-ДД`, `numeric` и `bigint` строкой, так что отличий в коде нет.

### 2. Папка данных и окружение

`gateway/src/lib/desktopEnv.js` — первым импортом в `server.js` и `migrate.js`. При `DTC_EDITION=desktop` всё, что
запускающий не задал, получает значения по умолчанию: `DB_DRIVER=pglite`, `PDF_ENGINE=js`, `GATEWAY_HOST=127.0.0.1`,
`DTC_DATA_DIR` — папка приложения ОС (создаётся с правами 700). Явно заданные переменные важнее. Gateway слушает
`GATEWAY_HOST:GATEWAY_PORT` (по умолчанию `0.0.0.0:3000`). Утренняя сводка и тревога о бэкапах на десктопе
не отправляются, `/health?deep=1` показывает `backup: off`. Запуск без Tauri для разработки: `scripts/desktop-dev.sh`
(docs/OPERATIONS.md). Tauri задаёт `DTC_EDITION=desktop`, `DTC_DATA_DIR`, `GATEWAY_PORT` и `APP_URL=http://127.0.0.1:<порт>`, остальное берётся по умолчанию;
`ORTHANC_*`, `EGRESS_PROXY` и `TELEGRAM_PROXY` в серверы не передаются.

`DTC_DATA_DIR`, папка приложения: macOS `~/Library/Application Support/MedControl`, Windows `%APPDATA%\MedControl`.
Там база (`pgdata`), загруженные файлы, секрет сессий (создаётся сам).

### 3. Процессы и окно

Проект Tauri 2 лежит в `desktop/` (см. «Как собрать»). Окно сначала показывает заставку `desktop/splash/index.html`. Код на Rust
(`desktop/src-tauri/src/lib.rs`) берёт два свободных порта на `127.0.0.1` и запускает встроенным Node сначала gateway
(`DTC_EDITION=desktop`, `DTC_DATA_DIR`, `GATEWAY_PORT`, `APP_URL`), потом сервер Next (`desktop-launcher.cjs`, `HOSTNAME=127.0.0.1`,
`GATEWAY_INTERNAL_URL`). Когда оба ответили, окно переходит на Next. Если запуск не удался, заставка показывает ошибку.
Журналы серверов лежат в `logs/` папки данных. Переменные окружения разработчика (`DATABASE_URL`, `NODE_OPTIONS` и т. п.)
в серверы не передаются.

Остановка без сигналов, одинаково на macOS и Windows: приложение держит stdin обоих серверов и при выходе закрывает его.
Gateway при `DTC_EXIT_WITH_PARENT=1` по закрытию stdin мягко останавливается и закрывает PGlite. Через 15 секунд всё,
что не остановилось, убивается. Если приложение упало, stdin закрывается сам, так что после выхода из меню, SIGTERM
или `kill -9` серверы останавливаются, а данные после перезапуска на месте. Второй запуск передаёт фокус первому окну
(`tauri-plugin-single-instance`). Плагина `shell` нет: Node запускается напрямую, IPC окну не нужен.

Размер на macOS arm64: `.dmg` около 71 МБ, приложение около 236 МБ (Node 112 МБ, gateway с зависимостями около 130 МБ).

- Node 22 как sidecar Tauri (`externalBin`) под каждую платформу: macOS arm64 и x64, Windows x64.
- Ресурсы: `gateway/` с production-зависимостями (`npm ci --omit=dev`: в отличие от Dockerfile, без `--omit=optional`, иначе не будет PGlite;
  нативных модулей нет, `pdfjs` без canvas), `shared/`, `locales/` (их читает gateway), `db/migrations`, сборка Next (словари интерфейса уже внутри неё)
  в режиме `standalone` (`frontend/.next/standalone` + `.next/static` + `public`), файлы wasm PGlite.
- Пути `../shared` и `../locales` в коде относительные: раскладка ресурсов повторяет репозиторий
  (`gateway/` рядом с `shared/` и `locales/`), как в Docker-образах.

### 4. Что поправить в WebView

Окно создаётся в коде (`desktop/src-tauri/src/lib.rs`), не в `tauri.conf.json`, чтобы повесить обработчики WebView.
Фронтенд для скачиваний и ссылок не менялся: работают обычные `<a download>` и `target="_blank"`.

- **Скачивания** (`on_download`): для любого скачивания — ZIP «Архива всех данных», PDF-отчёта, Excel, CSV, PDF бланка —
  открывается системный диалог «Сохранить файл» с именем из `download="…"` и папкой «Загрузки». «Отмена» отменяет
  скачивание, ошибка записи показывается окном. Диалог — `rfd`, без плагина `dialog` и без доступа страницы к файлам.
- **Ссылки** (`on_navigation`, `on_new_window`): внутри окна открываются только интерфейс (`127.0.0.1:<порт Next>`),
  заставка, `blob:` и `data:`. `http(s)` на чужие адреса, `mailto:` и `tel:` уходят в системный браузер, почту или телефон
  (`open`). Другие порты и адреса `127.0.0.1`/`localhost` (например, gateway напрямую) и прочие схемы (`file:`) не открываются.
  Правила — функция `route` с тестом (`cargo test` в `desktop/src-tauri`).
- **Вложения** (`window.open` с `blob:`): открываются во втором окне приложения, PDF и картинки WebView показывает сам.
- **Меню** на macOS по-русски: «МедКонтроль» (О программе, Скрыть, Завершить), «Правка» (копировать, вставить — без
  этого меню в macOS не работают ⌘C/⌘V), «Вид» (Обновить страницу ⌘R, Во весь экран), «Окно», «Справка» → «Открыть
  папку данных». На Windows строки меню нет, сочетания клавиш работают в WebView.
- **Тексты** по редакции (`frontend/app/ui/EditionText.tsx`, `useEdition`): подзаголовок мастера «История лечения на этом
  компьютере», подписи про хранение ключей в мастере и «Помощнике ИИ», раздел Настроек «Приложение → Служебное»
  вместо «Сервер → Для администратора сервера» с советом сохранять «Архив всех данных» в облако или на флешку.

- Service worker PWA (`frontend/app/ui/PwaRegister.tsx`) регистрируется только по `https:`, на `http://127.0.0.1` его не будет —
  так и нужно.

### 5. Безопасность

- Только `127.0.0.1`, секрет сессий генерируется в папке данных, вход по паролю из мастера первого запуска.
- Защита от DNS rebinding (чужая страница, чьё имя указывает на `127.0.0.1`): прокси Next принимает только `Host: 127.0.0.1:<порт Next>`, gateway — только `127.0.0.1` или `localhost` со своим портом или без него (`lib/hostGuard.js`; без порта шлёт проверка запуска в `lib.rs`), остальное получает 403. CORS gateway разрешает только `APP_URL`, без запасных `localhost:3001` серверной версии.
- Разрешения Tauri минимальные: сейчас у страниц нет IPC вовсе (нет capabilities и плагинов с командами); sidecar, диалог
  сохранения и открытие ссылок сделаны в Rust. DevTools выключены в релизной сборке.
- CSP как у edge (`edge/Caddyfile`): `default-src 'self'` и т. д.

### 6. Сборка и CI

- Имя приложения латиницей: `productName` «MedControl». Окно, меню и сообщения оболочки на русском, если система русская, иначе на английском (`sys-locale`); страницы внутри следуют настройке языка пользователя.
- GitHub Actions, `.github/workflows/desktop.yml`: собирает macOS arm64, macOS x64 и Windows x64. По тегу `vX.Y.Z` прикладывает установщики к Release этого тега под постоянными именами (`MedControl-macOS-AppleSilicon.dmg`, `MedControl-macOS-Intel.dmg`, `MedControl-Windows-Setup.exe`): ссылки в README вида `releases/latest/download/<имя>` всегда ведут на последнюю версию. Ручной запуск (Actions → desktop → Run workflow) только оставляет установщики артефактами на 14 дней, чтобы проверить ветку.
- Подписи разработчика и нотаризации пока нет: нужны аккаунт Apple Developer и сертификат для Windows. Приложение для macOS подписано без сертификата (ad-hoc, `signingIdentity: "-"`), с разрешением на JIT для встроенного Node (`entitlements.plist`): без такой подписи macOS называет скачанное приложение повреждённым.
  - macOS при первом запуске скажет, что не может проверить разработчика. Разрешить запуск: «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть». Если система всё же пишет «приложение повреждено», снимите карантин после копирования в «Программы»: `xattr -cr /Applications/MedControl.app`.
  - Windows покажет SmartScreen: «Подробнее» → «Выполнить в любом случае».
- Установщик для Windows один, NSIS (`.exe`). MSI не собирается: WiX не принимает файлы с нелатинскими именами внутри пакета.
- Автообновления нет: новая версия ставится поверх вручную, данные остаются в папке пользователя.

### 7. Проверка готовности

На чистой машине (macOS и Windows):

- первый запуск: страница с паролем, языком, часовым поясом и регионом, сразу после неё код восстановления пароля (почты и администратора у настольной версии нет, без кода забытый пароль не вернуть), затем пять шагов `/welcome` и переход на «Сегодня» с «С чего начать»;
- загрузка PDF бланка одной из четырёх встроенных лабораторий: МКНЦ, Хеликс, Хадасса, ДНКОМ (JS-движок), сводная, динамика, нормы;
- PDF-отчёт врачу, Excel и ZIP «Архива всех данных» сохраняются через диалог;
- ИИ с ключом: разбор незнакомого бланка, комментарий, чат;
- Telegram: напоминание приходит, пока приложение открыто;
- MCP: включить, подключить Claude Desktop на том же компьютере к `http://127.0.0.1:<порт>/api/gateway/mcp`;
- функции из таблицы выше видны с пометкой «только в серверной версии»;
- перезапуск приложения: данные на месте; удаление приложения не трогает папку данных.

Не входит: мобильная версия, автообновление, DICOM, Apple Health. Перенос данных с серверной версии и обратно:
«Архив всех данных» → «Скачать архив» на одной установке, «Загрузить архив» на новой (см. OVERVIEW.md, «Экспорт данных»).
