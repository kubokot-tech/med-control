# Восстановление МедКонтроля

Три копии, от быстрой к дальней:
1. `BACKUP_DIR` на сервере (`<BACKUP_DIR>/<дата_время>/`): `db.dump`, `uploads.tar.gz`, `env`. `BACKUP_KEEP` ночей (14).
   Секрета подписи сессий (`jwt.secret`) в копии нет: восстановленная установка создаёт новый, после восстановления нужно войти заново (если `JWT_SECRET` задан в `.env`, он остаётся прежним).
2. Второй диск (`MIRROR_DIR`): `backups/` то же самое, `dicom/` папки дисков.
3. Облако, зашифровано rclone crypt (`CLOUD_REMOTE`, в примерах `yc-crypt:`): `yc-crypt:backups/...` и `yc-crypt:dicom/...`. Ключ в менеджере паролей (две строки: password и salt).

Имя `yc-crypt:` даёт `scripts/cloud-setup.sh`: он настраивает одно S3-совместимое хранилище как пример. Служба backup работает с любым remote rclone из `CLOUD_REMOTE`, поэтому в командах ниже подставляйте своё имя, если подключали другое хранилище.

## А. Диск жив, нужно откатить данные
Из папки с кодом МедКонтроля (там, где `docker-compose.yml`):
```bash
./scripts/restore.sh ../medcontrol-backups/<дата_время> --yes   # или <BACKUP_DIR>/<дата_время>
```
Скрипт останавливает сервисы, восстанавливает базу и файлы, запускает обратно. Orthanc и DICOM не трогает.
Копия сначала разворачивается в новую базу и заменяет текущую, только если восстановилась целиком: при повреждённой копии текущие данные остаются как были. Копия, сделанная более старой версией, тоже подходит: после запуска программа сама доведёт схему базы до текущей.
Файл `.env` не обязателен. Папку с файлами скрипт берёт у контейнера gateway этого проекта (том или `DATA_DIR`),
поэтому соседние установки на той же машине (демо, тестовый стек) не задеваются. Если проект запущен с другим именем
(`docker compose -p <имя>`), добавьте `--project <имя>`; переменные стека (`APP_PORT`, `STACK_SUBNET` и т. п.) должны быть
те же, что при запуске, обычно они в `.env`. Если контейнеров ещё нет (новая машина), скрипт создаст их, не запуская.

## Б. Основной диск умер, сервер работает
1. Новый диск, Docker, папки под `DATA_DIR`, `PG_DIR`, `DICOM_DIR`.
2. `mkdir -p /srv/medcontrol/app && cd /srv/medcontrol/app`, распаковать репозиторий (git archive или zip с GitHub), `cp <MIRROR_DIR>/backups/<последняя>/env .env` (файла `env` нет, если на сервере не было `.env`).
3. `docker compose up -d postgres` → `./scripts/restore.sh <MIRROR_DIR>/backups/<последняя> --yes` → `docker compose up -d --build`.
4. DICOM: `rsync -a <MIRROR_DIR>/dicom/ <DICOM_DIR>/`, затем в Снимках → Архив снимков → «Импортировать» по каждой папке (Orthanc пересобирается из папок).

## В. Сервер потерян целиком: восстановление на любой машине из облака
Нужны: docker, rclone, ключ шифрования из менеджера паролей, ключи доступа к бакету.
```bash
# 1. rclone с теми же remote'ами, что были на сервере. После scripts/cloud-setup.sh это [yc] s3 и [yc-crypt] crypt с вашим password/salt
rclone lsd yc-crypt:backups            # список ночных копий
rclone copy yc-crypt:backups/<дата_время> ./restore/
cp ./restore/env <папка кода>/.env      # пароли, ключи, токены; файла нет, если на сервере не было .env
# 2. в папке кода: DATA_DIR/PG_DIR под новую машину, затем
docker compose up -d postgres && ./scripts/restore.sh ../restore --yes && docker compose up -d --build   # путь к копии от папки кода
# 3. DICOM при необходимости: rclone copy yc-crypt:dicom <DICOM_DIR>, потом импорт в Orthanc через Снимки
```
Доступ снаружи (домен, HTTPS-прокси, VPN-прокси) настраивается заново по ARCHITECTURE.md.

## Г. Из своего архива «Архив всех данных» (в том числе настольная версия и iPad)
Ночных бэкапов у настольной версии нет, её копия — ZIP из «Настройки → Архив всех данных → Скачать архив».
1. Поставить МедКонтроль заново (или серверную версию), пройти мастер первого запуска. Новый пароль может отличаться от старого.
2. «Настройки → Архив всех данных → Загрузить архив», выбрать ZIP, ввести пароль этой установки.

На iPad архив сохраняется через системное меню «Поделиться» (в «Файлы», iCloud и т.д.). Если iPadOS очистила
хранилище приложения, при следующем старте история поднимается из копии в контейнере приложения сама
(iPadOS 17.4+); архив нужен для переезда на другое устройство или если копия не поднялась.

Загрузка работает только в установке без записей. Переносятся записи, файлы, анамнез, протокол лечения и личные
настройки; ключи ИИ, Telegram и доступ для агентов заново настраиваются на новой установке. Снимки DICOM в архив не входят.

## Проверка
Каждое воскресенье сервис `backup` сам восстанавливает свежий дамп в базу `<db>_restore_test`, сверяет число строк в `lab_results`, `milestones`, `administrations`, `ai_comments` и пишет результат в `status.json`; он виден в Настройках и приходит утром в Telegram. Репетицию сценария В стоит делать раз в полгода на другой машине и записывать время.
