# Как выпускать версию

МедКонтроль живёт в двух репозиториях.

- **Рабочий.** Здесь идёт вся разработка: ветки, pull request, проверки, мерж в `main`. История подробная, со всеми промежуточными шагами.
- **Публичный** (`kubokot-tech/med-control`). Сюда попадают только выпуски, один коммит на версию. В нём лежит ровно то же дерево файлов, что в рабочем `main` в момент выпуска, но без истории разработки.

Переносит код один скрипт: `scripts/publish-public.sh`. Руками в публичный репозиторий ничего не пушим.

## Один раз: список запретов

Скрипт не запустится без файла со словами, которые не должны попасть в открытый код. Файл лежит вне репозитория и никуда не отправляется.

```bash
mkdir -p ~/.config/medcontrol
touch ~/.config/medcontrol/publish-deny.txt
chmod 600 ~/.config/medcontrol/publish-deny.txt
open -e ~/.config/medcontrol/publish-deny.txt
```

Одна строка, одно слово или регулярное выражение, регистр не важен. Строки с `#` в начале пропускаются. Что вписать:

- свою фамилию и фамилии близких, в разных написаниях (кириллица, латиница);
- домашний адрес, город и улицу;
- имена своих компьютеров, серверов и NAS, адреса домашней сети;
- названия своих клиник и лабораторий, номера заказов и карт.

Если найдено слово из списка, скрипт печатает только номер строки списка и файл, само слово не печатает. Хранить файл в другом месте можно так: `PUBLISH_DENY_FILE=/путь/к/файлу scripts/publish-public.sh …`.

## Каждый день

Работаем как обычно, но только в рабочем репозитории: ветка, PR, зелёные проверки, мерж в `main`. Каждое заметное изменение записываем в `CHANGELOG.md` в раздел «Не выпущено». Публичный репозиторий в это время не меняется.

## Выпуск

### 1. Подготовить версию

Одним PR в рабочем репозитории:

1. Проверить образцы бланков: `node scripts/lab-samples.mjs`. Есть новые: сначала парсер ([LAB-PARSERS.md](LAB-PARSERS.md), «Перед выпуском версии»). Код выхода 3 значит, что сервис не подключён: выпускать без этого.
2. Поменять номер версии во всех местах: `gateway/package.json`, `frontend/package.json`, `desktop/package.json` и их `package-lock.json`, `desktop/src-tauri/tauri.conf.json`, `desktop/src-tauri/Cargo.toml` и `Cargo.lock`, `gateway/src/server.js` (заголовок Swagger).
3. В `CHANGELOG.md` переименовать «Не выпущено» в `## X.Y.Z — дата` и сверху добавить пустой «Не выпущено». Первые строки раздела, до строки «Подробно:», станут текстом выпуска на GitHub: туда стоит вынести главное короткими пунктами.
4. Пересобрать список лицензий: `node scripts/third-party.mjs > THIRD-PARTY-NOTICES.md` (нужны установленные зависимости в `gateway`, `frontend`, `desktop`).
5. Дождаться зелёных проверок и влить PR.

### 2. Пробный прогон

```bash
git checkout main && git pull
scripts/publish-public.sh 0.4.0 --dry-run
```

Скрипт делает всё, кроме отправки, и печатает по шагам, что проверил:

- рабочая копия чистая, вы на свежем `main`, номер версии и раздел в `CHANGELOG.md` на месте;
- публичный репозиторий никто не трогал с прошлого выпуска;
- в коде нет ключей и токенов, путей вида `/Users/имя/`, лишних адресов почты и слов из списка запретов.

В конце он называет временную папку. В ней лежат копия публичного репозитория с готовым коммитом и файл `notes.md` с текстом выпуска. Их можно посмотреть, потом папку удалить.

### 3. Выпустить

```bash
scripts/publish-public.sh 0.4.0
```

Порядок такой:

1. Повторяются все проверки пробного прогона.
2. В публичный `main` уходит один коммит «МедКонтроль 0.4.0» от имени MedControl.
3. В рабочем репозитории ставится метка `public-v0.4.0`. По ней скрипт в следующий раз поймёт, что лежит в публичном репозитории.
4. Скрипт ждёт проверок (CI) в публичном репозитории, обычно 5–10 минут.
5. Если проверки зелёные, ставится тег `v0.4.0` и создаётся выпуск на GitHub.
6. Тег запускает сборку установщиков для Mac и Windows. Примерно через 15 минут они появляются в выпуске под постоянными именами, на них ведут ссылки в README.

Свой текст выпуска вместо собранного из `CHANGELOG.md`: `--notes файл.md`. Готовый текст из пробного прогона можно поправить и передать так.

### 4. Проверить после выпуска

- Страница выпуска: https://github.com/kubokot-tech/med-control/releases/latest, три установщика на месте.
- Ссылки на скачивание в README открываются.
- Ход сборки установщиков: `gh run list --repo kubokot-tech/med-control --workflow desktop.yml`.

## Если что-то пошло не так

**Проверки в публичном репозитории упали.** Коммит уже в публичном `main`, но тега и выпуска нет. Ссылку на упавшую проверку скрипт печатает. Исправить в рабочем репозитории обычным PR, влить и запустить ту же команду с тем же номером версии. Добавится ещё один коммит «МедКонтроль 0.4.0: исправление перед выпуском», дальше всё как обычно.

**«public main does not match».** Кто-то изменил публичный репозиторий в обход скрипта. Скрипт показывает, какие файлы различаются. Нужные изменения перенести в рабочий репозиторий, а лишние в публичном откатить.

**«deny pattern #N in: файл».** В файле нашлось слово из строки N списка запретов. Убрать его из кода в рабочем репозитории и выпускать снова. Если это ложное срабатывание (слово слишком общее), уточнить строку в списке.

**«secret or home path» или «email».** В коде нашёлся похожий на настоящий ключ, домашний путь или адрес почты. Убрать. Разрешены адреса на `example.com`, `med-control.app`, `users.noreply.github.com`.

**«v0.4.0 is already released».** Такая версия уже вышла. Поднять номер.

**Проверки не начались за 5 минут.** Скрипт останавливается без тега. Посмотреть вкладку Actions публичного репозитория и запустить скрипт ещё раз: если код не менялся, он не создаст новый коммит, а сразу будет ждать проверок.

## Pull request от участников

Если кто-то прислал PR в публичный репозиторий, вливать его там нельзя: следующий выпуск остановится на проверке. Изменения переносятся в рабочий репозиторий руками, лучше с упоминанием автора в описании и в `CHANGELOG.md`, и уходят со следующим выпуском. PR в публичном репозитории закрываем с комментарием, в какой версии изменение выйдет.

## Чего скрипт не видит

Скрипт ищет текст. Картинки, PDF и другие двоичные файлы он не читает, кроме их имён. Новые скриншоты и примеры бланков перед выпуском нужно просмотреть глазами: на них не должно быть настоящих имён, анализов и адресов.
