# Языки и региональные настройки

Решено 2 ноября 2026. Интерфейс на русском и английском, новый язык добавляется файлами перевода; другой формат даты или другие единицы анализов включаются в Настройках, без правок по всему коду.

## Две оси: язык и регион

- **Язык** определяет слова: подписи, ошибки, тексты отчёта и бота, язык ответов ИИ.
- **Регион** определяет форматы: дату, время, разделитель дробной части, первый день недели, единицы измерения.

Это разные настройки. Русскоязычный пациент в США может смотреть глюкозу в мг/дл, англоязычный в Европе в ммоль/л.
Регион задаёт значения по умолчанию, каждую из них можно поменять отдельно.

## Настройки «Язык, регион, часовой пояс»

Хранятся у пользователя: `users.locale` (язык) и `users.prefs` (jsonb с форматами, миграция 031), часовой пояс уже есть в `users.timezone`. API: `GET`/`PUT /settings/locale` (в `PUT` можно сменить и часовой пояс; токен сессии хранит пояс, поэтому ответ приносит новый токен).
Значения по умолчанию для новой установки задаёт мастер первого запуска.

| Настройка | Значения | По умолчанию для `ru-RU` |
|---|---|---|
| Язык интерфейса | `ru`, `en` | `ru` |
| Регион | код BCP 47: `ru-RU`, `en-US`, `en-GB`, `de-DE`… | `ru-RU` |
| Часовой пояс | IANA, уже есть | `Europe/Moscow` |
| Формат даты | по региону · `ДД.ММ.ГГГГ` · `ММ/ДД/ГГГГ` · `ГГГГ-ММ-ДД` | по региону |
| Время | по региону · 24 часа · 12 часов | по региону |
| Первый день недели | по региону · понедельник · воскресенье | по региону |
| Единицы анализов | СИ (ммоль/л, мкмоль/л, г/л) · традиционные (мг/дл, г/дл) | СИ |
| Температура | °C · °F | °C |
| Вес | кг · фунты | кг |

«По региону» значит: берём то, что для региона знает `Intl` (дату, время, разделитель, первый день недели через `Intl.Locale.weekInfo`
с запасным списком для движков без неё).

## Правило хранения: всегда канонично, преобразуем только на краях

В базе одна форма для всего, независимо от настроек:

- моменты времени в `timestamptz`, календарные дни строкой `ГГГГ-ММ-ДД`;
- результаты анализов в канонической единице показателя из справочника (это уже так: `lib/units.js` приводит при записи);
- температура в °C (`temp_c`), вес в кг (`weight_kg`);
- числа числами, без форматирования.

Преобразование по настройкам происходит только в двух местах: при показе (интерфейс, PDF-отчёт, бот, текст для ИИ) и при вводе
(пользователь ввёл 101,3 °F, сохраняем 38,5 °C). Поменять настройку можно в любой момент: данные не пересчитываются, меняется только показ.

## Единицы анализов

У показателя в справочнике (`lib/catalogSeed.js`) есть каноническая единица (СИ). Для системы «традиционные» таблица
`shared/units.js` (`CONVENTIONAL`) задаёт вторую единицу и коэффициент: глюкоза мг/дл, креатинин мг/дл, гемоглобин г/дл,
холестерин мг/дл, лейкоциты ×10³/мкл и т. д. Пересчитываются значения, нормы и разница с прошлым значением в ответах API
(`lib/labDisplay.js`), выгрузках и отчёте врачу; своя норма вводится в выбранных единицах и хранится в СИ. Значение, которое
не удалось привести к канонической единице, показывается как хранится. Пороги тревог протокола и тексты для ИИ остаются в СИ.
Позже можно разрешить выбор единицы для отдельного показателя.

Распознавание бланков от этих настроек не зависит: парсер читает то, что напечатано, `units.js` приводит к канону.

## Тексты интерфейса

1. **Сервер отдаёт данные и коды, а не готовые фразы.** `kind: 'surgery'`, а не `kindLabel: 'Операция'`; код ошибки, а не сообщение
   (для ошибок так уже сделано: тексты в `locales/ru/errors.json`). Подпись выбирает тот, кто показывает.
2. **Готовые подписи не хранятся в базе.** Заголовок события ленты «Операция: Резекция» собирается при показе из вида и названия.
   Существующие записи переводятся одной миграцией.
3. **Одни словари на весь проект**: `locales/<язык>/<раздел>.json` в корне репозитория (`locales/ru/errors.json`, `locales/en/errors.json`).
   Раздел на экран или тему: так PR по разным экранам не мешают друг другу. Ими пользуется фронтенд и gateway (оба образа собираются
   из корня, в контекст сборки попадают только нужные папки, см. `.dockerignore`). Тексты, которые пишет только gateway, лежат в
   `locales/<язык>/server/<раздел>.json` и во фронтенд не попадают: названия показателей (`markers`), шкалы дневника (`scales`), пресеты
   протокола (`presets`), тексты тревог (`alertTexts`), заголовки ленты (`feedTitles`), частота приёма (`schedule`), заголовки поиска
   (`searchTitles`). Имя раздела уникально в обеих папках.
4. **Формат сообщений ICU** (`{n, plural, one {# анализ} few {# анализа} many {# анализов}}`): у каждого языка свои формы
   множественного числа, переводчик описывает их сам, код не меняется. Фронтенд: `use-intl` (ядро `next-intl` без серверной части:
   почти все экраны клиентские, маршрутов по языку нет, настольная версия собирает тот же фронтенд). Gateway: `intl-messageformat`, тот же
   формат, через `lib/i18n.js`: `t(язык, 'раздел.ключ', аргументы)`.
5. **Ключи по разделам**: раздел — файл, внутри вложенные ключи: `useTranslations('common')` и `t('nav.today')`. TypeScript проверяет,
   что ключ есть в русском словаре (`frontend/app/i18n/types.d.ts`).
6. **Ответы ИИ** на языке пользователя; системные подсказки модели тоже переходят в словари.
7. **Справочные данные с устойчивыми ключами**: показатели (`ALT`, `CREA`), виды вех, шкалы дневника, пресеты. Названия показателей
   лежат в словаре `markers` по ключу справочника, русская сторона совпадает с `catalogSeed.js` слово в слово (это проверяет тест),
   в базе остаются `name_ru`/`short_ru`. Синонимы для распознавания бланков остаются на языке бланка.
8. **Записи пациента не переводятся**: заметки, названия из бланков, заключения врачей остаются как введены.
9. **Парсеры лабораторий вне локализации**: они привязаны к формату бланка, а не к языку интерфейса.

## Тексты, которые пишет gateway

`lib/i18n.js` читает словари с диска: `t(язык, 'раздел.ключ', аргументы)` для сообщений ICU, `raw()` для шаблонов, которые gateway заполняет сам.
Ключа нет в языке: берётся русский, это исходный язык. В ключах серверных словарей можно `#`, `%` и `-`: это ключи справочника и пресетов (`NEUT#`, `U-PRO`).
Папка `locales/` лежит рядом с `shared/` и в образе gateway, и в настольном пакете (`gateway/Dockerfile`, `desktop/scripts/prepare.mjs`).
Язык берётся из `users.locale`: `getUserLocale`, `userFormat` или `userLanguage` (`lib/userLocale.js`); конвертер единиц `userLabUnits` уже знает язык, лишнего запроса на экранах анализов нет.

Где решает фронтенд, а где gateway:

- **Коды, подпись выбирает экран:** модальность (`imaging.modality`), способ введения (`infusions.route`), ответ на лечение (`imaging.responseLabel`), вид вехи (`history.kindLabels`), сервис ИИ (`settings.aiCard.provider`). В базе модальность и способ введения остаются словами («КТ», «в/в капельно»), код сравнивает и группирует по ним; таблица «значение → код» в `shared/medCodes.js`. Значение не из таблицы показывается как есть. Поля `kindLabel`, `responseLabel`, `responses` в ответах API идут на языке пользователя, их читают инструменты MCP.
- **Ошибки:** экран берёт текст по коду из `errors.json`. Поле `message` в ответах gateway осталось по-русски, поэтому `ui/api.ts` показывает его только на русском экране; на другом языке сначала идёт код, и `message` нужен, только если кода нет в словаре.
- **Единицы:** `displayUnit(единица, язык)` в `shared/units.js`, на экранах `f.unit()`. Перевод по токенам, поэтому переводится и написание лаборатории; единица с незнакомым словом остаётся целиком. Меняется только показ: в базе и в сравнениях единицы прежние, а `unitFamily` понимает обе записи, поэтому единица, введённая на английском экране, приводится к той же канонической.
- **Подписи готовит gateway:** названия показателей (`markerName`, `markerShort`, `catalog(язык)`), шкалы (`scaleCatalog(язык)`), частота приёма (`describeSchedule(item, язык)`), сводка дня дневника (`summarize`).
- **Разделы `server/`:** бот и напоминания `bot`, уведомления `notify` (`lib/notifyUser.js`), отчёт врачу `doctorReport`, выгрузки анализов `labsExport`, файл для ИИ-приложений `dossier`, архив `exportArchive`, инструменты MCP `mcp`, подсказки модели `aiPrompts`, данные для модели `aiContext`.

### Подсказки модели

Системные подсказки лежат в `locales/<язык>/server/aiPrompts.json` и читаются через `lib/aiPrompts.js` (`prompt`, `patientPrompt`), подписи в тексте данных в `aiContext.json`. Модель отвечает на языке пользователя: это написано в подсказке. Профиль кэшируется на язык. На одном языке текст подсказки один для всех, поэтому кэш подсказок у провайдера работает. Подсказки разбора бланков и заключений на любом языке принимают русские документы; значения переносятся как напечатаны, контракт JSON один. Хэши русских подсказок записаны в `gateway/test/serverTexts.test.js`: правка меняет кэш и требует медицинской вычитки.

### Бот понимает оба языка

Команды и дневник одной строкой (`lib/symptomsText.js`, слова шкал в `diaryScales.js`) работают на обоих языках при любой настройке, язык определяет только ответ. Число без единицы считается в единицах пользователя, написанная единица (kg, lb, °F) важнее, в базе всегда кг и °C. «yes» и «no» считаются отметкой только отдельным словом: «no nausea» это дневник.

### Что хранится по-русски

- **Пресеты протокола.** Тексты пресета лежат в словаре `presets`, в `protocolPresets.js` только структура: пороги, шкалы, дозы. В `app_settings` тексты пресета всегда хранятся по-русски, как единицы хранятся в одной форме: `protocolIn(протокол, язык)` переводит их по пути на экран и обратно при сохранении, поэтому английский экран не превращает пресет в «свой протокол», а подсказки для ИИ не меняются. То, что пользователь изменил или написал сам, не переводится и остаётся как написано.
- **Сгенерированные записи.** Новые тревоги и заголовки ленты пишутся на языке пользователя. Уже записанные не трогаем и миграцию не делаем: на пути к экрану `relocalize()` узнаёт наш шаблон на другом языке и пишет его заново на языке читателя (`lib/eventText.js`, `rowToAlert` в `lib/alerts.js`); имена и текст пользователя внутри шаблона остаются как были. Строка на языке читателя не разбирается вообще, поэтому русский читатель получает сохранённый текст байт в байт. Сводка дня дневника на другом языке собирается заново из записи дня.
- **Служебные слова.** Заметки «календарь», «до отметок по приёмам» и причина дозы «назначение» работают как коды: `deleteDose` сравнивает с ними, поэтому в базе они остаются по-русски, а показывает их `doseNote()`.

Остаётся по-русски на английском экране только то, что ввёл человек или что пришло с бланка: названия препаратов, заметки, названия из бланков, заключения. Название стандартного препарата, добавленного из пресета по-русски, тоже запись пациента и не переводится. Уже полученные ответы ИИ (вопросы к приёму, комментарии) тоже остаются на языке, на котором написаны.

Таблицы `tables/*.json` в архиве всех данных хранят записи как в базе: архив загружается обратно, поэтому сгенерированные тексты в них не переводятся. Метка страниц `<!-- страница N -->` в извлечённом тексте остаётся служебной: одинаково пишется в серверном разборе и в распознавании. Сообщения сторожа (`watchdog.sh`) не знают настроек пользователя, язык задаёт `WATCHDOG_LANG` в `.env`.

## Английская версия: термины

Продукт называется **MedControl**, сокращение **MC**; «МедКонтроль» в английских текстах не встречается. Копилайн: *Your whole treatment history, close at hand.*
Голос тот же, что в [BRAND-VOICE.md](BRAND-VOICE.md): спокойный, взрослый, конкретный. Американское написание, в кнопках и заголовках заглавная только первая буква, без длинных тире, без рекламных слов (smart, seamless, powerful). Обращение на you, без предположения, что пользователь сам пациент.

## Даты и числа в коде

- Никаких `'ru-RU'` и ручных форматов дат: всё через общий модуль форматирования, который знает язык, регион, часовой пояс и настройки.
  На фронтенде хук `useFormat()` (`frontend/app/ui/format.tsx`), в gateway `userFormat(userId)` (`lib/userLocale.js`) для того, что читает
  человек: PDF-отчёт, выгрузки, бот, тексты тревог, строка бэкапа. Тексты для ИИ (профиль, досье, вопросы к приёму, итог месяца)
  идут через `lib/aiFormat.js`: формат языка подсказки, а не региона пользователя, свой для каждого языка. Модели всё равно, а одинаковый текст сохраняет кэш подсказок.
  Значение вида `ГГГГ-ММ-ДД` форматтер считает календарным днём и не сдвигает по часовому поясу; время приёма, записанное текстом (`14:30`), показывает `clock()`.
- Ввод дат в формах через нативные поля (`<input type="date">`): браузер сам показывает их в формате системы, значение всегда ISO.

## Как перенести тексты экрана в словарь

1. Создать `locales/ru/<раздел>.json` (или дописать существующий) и подключить файл в `frontend/app/i18n/messages.ts`.
2. В компоненте `const t = useTranslations('<раздел>')`, текст заменить на `t('ключ')`; подстановки и числа через ICU:
   `t('count', { n })` с `{n, plural, one {# запись} few {# записи} many {# записей} other {# записи}}`. Готовые фразы из кусков
   не склеивать: порядок слов в другом языке другой, во фразе должна быть переменная.
3. Даты и числа по-прежнему через `useFormat()`, единицы через `f.unit()`.
4. Записать новые числа: `node scripts/i18n-baseline.mjs > frontend/i18n-baseline.json`.
5. Серверные компоненты (метаданные страниц) берут тексты через `serverT('<раздел>')` из `frontend/app/i18n/server.ts`.

## Защита от возврата к старому

- Тест `gateway/test/i18n.test.js`: строк с кириллицей в файле интерфейса не больше, чем записано в `frontend/i18n-baseline.json`, и число
  только уменьшается (сколько осталось, видно в поле `total`). Когда вынесено всё, файл станет пустым, и тест превратится в запрет.
- Тест `gateway/test/serverTexts.test.js`: в файлах, откуда вынесены тексты бота, отчёта, выгрузок и подсказок, кириллицы вне комментариев нет; русские подсказки совпадают с записанными хэшами. Кириллица в gateway остаётся в парсерах лабораторий, справочнике синонимов, словах бота и дневника, сообщениях `message` при ошибках и демо-наборе.
- Тест: во всех языках одинаковые разделы и ключи, включая `server/`, каждое сообщение разбирается как ICU и подставляет те же переменные, что русское;
  каждый раздел интерфейса подключён во фронтенде, а `server/` не подключён.
- Тест `gateway/test/i18nServer.test.js`: русский словарь показателей совпадает с `catalogSeed.js`, в пресетах на всех языках одни пороги, русский читатель получает сохранённые строки без изменений. `gateway/test/integration/i18nApi.test.js`: те же данные в API на `ru` и `en`.
