# Как устроен проект и как в нём участвовать

## Политика поддержки

МедКонтроль — проект одного пациента, который ведёт его в свободное время. Это значит:

- **Без гарантий и сроков.** Issue могут лежать без ответа неделями; исправления выходят, когда до них доходят руки.
- **Без поддержки установки под конкретное железо.** Проверяется одна конфигурация: Docker Compose на домашнем сервере.
  Вопросы вида «не запускается на моём NAS» лучше оформлять как issue с логами, но ответ не обещается.
- **Клинические пороги не проверяются.** Правила тревог и пресеты протоколов лечения — примеры. Pull request с новым
  пресетом принимается только с пометкой «пример, не проверен врачом», см. [DISCLAIMER.md](DISCLAIMER.md).
- **Уязвимости** сообщайте приватно, не через issue: [SECURITY.md](SECURITY.md).
- **Личные данные в репозиторий не попадают.** Ни в код, ни в тесты, ни в документацию, ни в примеры PDF.
  Фикстуры только условные (вымышленные имена, даты, лаборатории).

## Как предложить изменение

Демо-стенд для проверки своих изменений на живых данных: `scripts/demo.sh` (см. `docs/OPERATIONS.md`). Переводы интерфейса и документации на другие языки приветствуются. Особенно ценны парсеры бланков новых лабораторий: протокол в `docs/LAB-PARSERS.md`.

1. Небольшой PR с одной темой. Документацию обновлять в том же PR.
2. Интерфейс на русском и английском: новый текст добавляется в оба словаря (`locales/ru`, `locales/en`). Документация и описания коммитов на русском или английском. Код и комментарии в коде — английский.
3. Перед PR прогнать тесты:
   - `cd gateway && npm test` — юнит-тесты;
   - `npm run test:integration` с `TEST_DATABASE_URL` на отдельной базе — интеграционные (см. `docs/OPERATIONS.md`); без Postgres: `TEST_DB=pglite npm run test:integration`;
   - `cd frontend && npm run typecheck`;
   - если меняли парсеры лабораторий: `cd ingestion && python -m pytest -q` (см. `docs/LAB-PARSERS.md`).
4. Миграции только добавляющие и идемпотентные (см. `docs/ARCHITECTURE.md`, раздел «Миграции»).
5. Секреты только в `.env`; в коде и примерах не должно быть ключей, адресов и паролей.

## Куда смотреть

- `docs/OVERVIEW.md` — что умеет каждый экран.
- `docs/ARCHITECTURE.md` — компоненты, модель данных, карта модулей.
- `docs/OPERATIONS.md` — запуск, деплой, типичные поломки.
- `docs/ROADMAP.md` — что запланировано.
- `docs/RELEASE.md` — как выходит версия: принятые PR попадают в публичный репозиторий со следующим выпуском.
